# Agent Pi 2.3.0 / Agent π 2.3.0

Agent Pi 2.3.0 introduces a bounded Self-Harness layer for recurring execution failures and quality corrections. It learns only from verified recovery evidence and never rewrites production code at runtime.

Agent π 2.3.0 新增有边界的 Self-Harness 执行层，用于处理反复出现的工具失败和质量纠错。系统只从已验证的恢复证据中学习，不会在运行时自行改写生产代码。

## Highlights / 亮点

- **Bounded tool recovery** - An identical failed tool call may be retried once. A second identical failure blocks that route and requires changed input, a verified fallback, or user review, preventing token-consuming retry loops.
- **有边界的工具纠偏** - 同一个失败工具调用最多原样重试一次；第二次相同失败后必须修改参数、采用已验证替代路线或转人工复核，避免重复循环浪费 token。
- **Verified route reuse** - Successful changed-call recoveries are stored as sanitized input shapes and matched to similar future tasks by provider, model, and mode. At most three advisory hints are injected.
- **成功路线复用** - 修改调用后成功的恢复路线会以脱敏输入形状保存，并按供应商、模型和模式匹配相似任务；每次最多注入三条建议。
- **Quality feedback regression ledger** - Explicit user corrections for scope, coverage, template, depth, evidence, format, or tools become deduplicated regression candidates instead of silently changing global behavior.
- **质量反馈回归账本** - 用户明确指出的范围、覆盖、模板、深度、证据、格式或工具问题会形成去重回归候选，不会静默改变全局行为。
- **Constrained policy promotion** - Harness policies use a non-executable rule DSL with versions, hashes, and rollback links. Promotion requires target improvement, no held-out regression, and a fully passing protected suite.
- **受限策略晋升** - Harness 策略采用不可执行的规则 DSL，带版本、哈希和回滚链；只有目标用例提升、留出用例不退化且保护用例全部通过时才能晋升。
- **Deterministic BOQ completion** - BOQ completion depends on exact assigned item IDs, counts, schema validation, child-to-parent equality, and contradiction detection. A completion claim cannot substitute for missing item evidence.
- **BOQ 确定性完成门禁** - BOQ 完成取决于分配条目 ID、数量、结构校验、子报告与合并结果一致性及矛盾检测；智能体自称完成不能替代缺失证据。
- **Executable template fidelity** - Uploaded reference templates are parsed into section order and DOCX layout constraints. Strict delivery compares the exported DOCX page, orientation, margins, fonts, styles, numbering, header/footer structure, table styles, and caption styles.
- **可执行模板复刻** - 上传参照模板会被解析为章节顺序和 DOCX 版式约束；严格交付会核对导出 DOCX 的纸张、方向、页边距、字体、样式、编号、页眉页脚结构、表格样式和题注样式。
- **Harness status in the existing UI** - The Information panel shows matched routes, recovery decisions, verified route counts, feedback, and regression candidates; the Goal badge keeps only a compact recovery hint.
- **现有界面中的 Harness 状态** - 信息弹窗显示命中路线、纠偏决策、已验证路线数量、反馈和回归候选；Goal 标记仅增加简洁恢复提示。
- **Passive crash recovery** - Opening the app no longer replays a queued user message left by a previous crash. The interrupted turn stays visible and resumes only after an explicit user action.
- **被动式崩溃恢复** - 打开应用不再自动重放上次崩溃遗留的排队消息；中断记录继续保留，但只有用户明确操作后才会恢复执行。
- **Renderer crash auto-recovery** - When the UI renderer crashes under multi-sub-agent load, the window reloads instead of disappearing and quitting the whole Windows/Linux app. Crash loops are rate-limited.
- **Renderer 崩溃自动恢复** - 多子智能体负载下 UI renderer 崩溃时，窗口会自动重载，而不是直接消失并退出整个 Windows/Linux 应用；连续崩溃会受到频率限制。
- **Spawn memory soft-guard** - `spawn_session` is blocked when main-process RSS or total Electron working set crosses soft limits, reducing out-of-memory exits while many child agents are already running.
- **子智能体内存软保护** - 主进程 RSS 或 Electron 总工作集超过软阈值时会阻止继续 `spawn_session`，减少大量子智能体运行时的内存耗尽退出。
- **Runtime-owned child handoffs** - After dispatching structured child work, the parent model yields immediately. A lightweight runtime monitor waits for handoffs, while child workers run without nested Goal Loops, eliminating model-driven polling storms.
- **运行时接管子智能体交接** - 派出结构化子任务后主模型立即让出执行权，由轻量运行时监控交接；子智能体不再嵌套 Goal Loop，避免主智能体高频轮询和循环堆积。
- **Tender closeout readiness bridge** - Tender Workbench recognizes audited `STAGE_CLOSEOUT*.md` evidence for `document_analysis` and persists it into `capability-index.json`, unblocking downstream stages without fabricating BOQ data packs.
- **投标收尾证明解锁** - 投标工作台可识别经审计的 `STAGE_CLOSEOUT*.md` 中的 `document_analysis` 证明，并写入 `capability-index.json`，在不伪造 BOQ 数据包的前提下解锁后续阶段。
- **Long-session stability** - Processing-stop cleanup is idempotent per turn, stale callbacks cannot audit a newer turn, persistence materializes only the latest debounced history snapshot, and restored searches cannot mount the entire conversation at once.
- **长会话稳定性** - 每轮收尾只执行一次，旧回调不能审查新一轮；持久化只生成最新防抖快照，恢复搜索也不会一次挂载全部历史，避免长任务内存持续膨胀。

## Safety Boundary / 安全边界

V2.3 does not implement live self-modifying code, generated executable policies, or unrestricted autonomous evolution. Learned routes remain advisory, exact repeated failures are bounded, and cross-task policy changes require regression-gated approval and rollback metadata.

V2.3 不实现运行时自改代码、模型生成可执行策略或无边界自治进化。学习到的路线保持建议性质，相同失败受到次数限制，跨任务策略变更必须通过回归门禁并保留回滚信息。
