# Agent Pi 2.6.0 / Agent 派 2.6.0

Agent Pi 2.6.0 makes tender jurisdiction and project boundary an explicit, confirmable desk before BOQ pricing, hard-fences pricing briefs to that pack, and ships workbench UX that stays usable while long jobs run: force-pass on the monitor, live HTML artifacts, and a file tree that no longer refreshes out from under the cursor.

Agent 派 2.6.0 把辖区与项目边界做成组价前可确认的登记台，组价 brief 以该包为硬围栏；同时补齐长任务下的工作台体验：监控顶栏强制放行、HTML 产物按完整网页运行、右侧文件树不再自动刷新把要点的文件刷没。

## Features

- **Project boundary desk + BOQ fence** — Between document analysis and BOQ pricing, 项目边界条件 is a registration/confirmation desk (not a silent scan). Users pick enterprise knowledge-base entries, bind this-tender specs, and attach bidder-owned files. The parent session parses them into `project_boundary`; that pack is injected into BOQ briefs as a hard fence (`allowedSourceIds` / extracted inventory). Unconfirmed or still-parsing packs cannot unlock pricing. Overview has **打开边界登记/确认**.
- **项目边界登记台 + 组价硬围栏** — 招标文件解析与 BOQ 组价之间的「项目边界条件」是登记/确认台。用户选择企业知识库条目、绑定本标规范、附上投标人自有文件；主会话解析写入 `project_boundary`，该包作为组价 brief 硬围栏。未确认或仍在解析时不能解锁组价。
- **Jurisdiction profiles** — New projects default to `generic-international` (`knowledge/tender-generic/`). SANRAL/C5.1 remains `sa-sanral-highway`. Registry: `knowledge/profiles.json`.
- **辖区 Profile** — 新项目默认 `generic-international`；SANRAL/C5.1 仍可选 `sa-sanral-highway`。
- **DeepSeek vision bridge** — DeepSeek V4 Flash/Pro cannot see images natively. In Settings → AI → Edit a DeepSeek connection, enable **Vision support** and paste a VLM API key (Zhipu GLM-4.6V Flash is free by default; DashScope / Ollama / custom OpenAI-compatible endpoints also work). Attached images are read in the same turn and given to DeepSeek as text.
- **DeepSeek 视觉桥** — DeepSeek V4 不能直接看图。在设置 → AI → 编辑 DeepSeek 连接中开启「视觉支持」并填入 VLM Key（默认智谱 GLM-4.6V Flash 免费档；也支持百炼 / Ollama / 自定义兼容端点）。附件图片在同一轮读成文字再交给 DeepSeek。

## Improvements

- **Force-pass on the monitor toolbar** — 流程监控 shows **强制放行** next to 检查 when a stage is blocked or missing items (including blocked planning substeps). Stage rows use the same gate; waived items are recorded and completed batches are not deleted.
- **监控强制放行** — 流程监控顶栏「检查」旁提供「强制放行」；阶段阻塞、缺件或策划子步骤缺件时可点。已完成批次不会被删。
- **Live HTML artifacts** — Session-file `.html` / `.htm` opens as a full webpage (scripts, relative CSS/JS, `/assets/` paths) instead of a clipped `srcDoc` preview. **Open in browser** launches the in-app browser window. Chat `html-preview` blocks stay sandboxed without scripts.
- **HTML 产物完整网页** — 右侧文件树打开 HTML 按完整网页运行动态组件；可「在浏览器打开」。对话里的 `html-preview` 块仍沙箱且默认禁脚本。
- **Session Files refresh on demand** — The right-hand file tree no longer auto-reloads on every disk write. It reloads on session change, folder expand, or the refresh button, so expanded folders do not vanish while you click.
- **会话文件按需刷新** — 右侧文件树不再随磁盘写入整树刷新；切换会话、展开文件夹或点刷新才更新。
- **Tender writing contract** — Parse memos, BOQ workpapers, boundary notes, methodology, programme/cash-flow narratives, and formal returnables must be tender-grounded professional bid writing with AI filler stripped. Injected into stage drafts and child briefs.
- **投标写作契约** — 解析纪要、组价底稿、边界说明、方法论、进度/资金叙述和正式回标文件须紧扣招标资料、去掉 AI 套话；注入阶段草稿与子任务 brief。
- **Professional document-analysis memos** — Batch briefs carry industry/document-role guidance; merge summaries drop pack-path tutorial tone; meta-dense MD is flagged softly.
- **专业文档分析纪要** — 批次 brief 带行业/文档角色指引；合并摘要去掉 pack 路径教程腔。
- **Polymorphic BOQ pricingStandard** — Quality checks follow the boundary pack (`c51_pure_direct_cost_v1` vs `generic_direct_cost_v1`) instead of a global COTO assumption.
- **多态 BOQ 计价标准** — 质量检查跟随边界包的 `pricingStandard`。
- **Packaged runtime** — Claude Agent SDK **0.3.228**; Pi stays on latest **0.84.1**.
- **打包运行时** — Claude Agent SDK **0.3.228**；Pi **0.84.1**。

## Bug Fixes

- **Tender Official Outputs missing BOQ MD** — After pricing batches complete, chapter workpapers, the labour/plant/material schedule (`施工资源消耗总表.md`), and a stage completion summary are published into `Agent Pi Outputs/<parentSessionId>/` so Session Files 「正式输出」 lists them. Cross-batch resource unit/rate conflicts remain review items and no longer block the resource-schedule pack write.
- **正式输出缺少组价 MD** — 组价批次完成后，章节底稿、施工资源消耗总表和阶段完成摘要发布到主会话正式输出目录；跨批资源单价冲突改为复核项，不再卡住资源总表写入。
- **Resume fill-up serialized to one child** — Idle children are continued in parallel chunks up to `maxConcurrency` (default 4). Dead left-rail bindings are cleared so resume can spawn cleanly.
- **恢复补位只能跑一个对话** — 空闲子会话分批并行续跑直至并发上限；左侧已删除的会话绑定会被清理。
- **Standby/wake resume exited the app** — After OS sleep, dead Pi subprocess stdin writes (`write EPIPE`) are handled and idle runtimes are disposed on `powerMonitor.resume`; continue cold-starts honor the spawn memory guard.
- **待机恢复后重启分析直接退出** — 休眠唤醒后僵死子进程的 `EPIPE` 不再冲垮主进程；接续冷启动受内存软门禁约束。
- **HTML preview blank / in-app browser failed** — Live HTML used a `user@host` custom URL that Chromium lowercases/strips, and the in-app browser session never received the `agent-preview://` handler. Previews now encode the folder in a lowercase-safe hostname and register the protocol on both the default and browser-pane sessions.
- **HTML 预览空白 / 无法创建浏览窗口** — 完整网页预览的自定义协议改为 hostname 编码，并在内置浏览窗口的独立 session 上注册；工具栏补上 i18n，地址栏不再显示 `browser.urlPlaceholder`。
- **Switching conversations froze the chat pane** — Opening a large tender parent session shipped the full JSONL (multi-MB tool results) over IPC, waited for the previous transcript to unmount, and raced the file tree plus live stage monitor on the main process. The spinner looked dead. Chat now loads a display projection, reads JSONL without blocking the event loop, shows a loading label, and lets the file tree / monitor wait until the transcript is ready.
- **切换对话卡死转圈** — 投标主会话打开时会把整份 JSONL（含数 MB 的工具结果）打进渲染进程，还要等旧对话卸完，并和右侧文件树、流程监控抢主进程，界面像死机。现在聊天只加载展示用摘要、异步读盘、显示「正在加载」，文件树和监控让路给对话。
- **Model-switch remount blocked session tools and extra MCP** — After changing models, Pi session tools threw `Cannot set property workingDirectory` (getter-only live binding), so `get_session_info` / `activate_source` failed. The orchestration source fence also stayed frozen on the original snapshot (e.g. anysearch) while newly remounted MCP tools were already present. Session-tool context now accepts the working-directory assignment, and the selected-source policy tracks live enabled sources.
- **换模型重挂后会话工具与出图 MCP 被墙** — 切换模型后 Pi 会话工具因只读 `workingDirectory` 绑定抛错，诊断/扩源全部失败；源边界快照仍停在 anysearch，新挂上的出图等 MCP 继续被围栏拦截。现已补 setter，并把围栏与当前已启用源对齐。
