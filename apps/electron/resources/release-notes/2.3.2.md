# Agent Pi 2.3.2 / Agent π 2.3.2

Agent Pi 2.3.2 fixes tender workbench batch retry false-failures, and uplifts Claude Agent SDK and Pi runtime patch/minor versions.

Agent π 2.3.2 修复投标工作台批次重试误报失败，并升级 Claude Agent SDK 与 Pi 运行时。

## Bug Fixes / 修复

- **Tender stage retry no longer marks capacity waits as failed** — When "Retry failed batches" hit `spawn_session active handoff limit` (or the spawn memory guard), the task board previously wrote those batches as `failed` even while other children kept running. Overflowed work now stays `pending` and is re-dispatched on later status polls as slots free. Stale invalid child reports are quarantined on retry so schema-invalid leftovers cannot clobber an in-flight re-run.
- **投标阶段重试不再把容量等待误标为失败** — 点击「重试失败批次」时若触发 `spawn_session active handoff limit`（或 spawn 内存保护），任务板此前会立刻把后续批次写成 `failed`，而其他子会话仍在运行。现在超限任务保持 `pending`，由后续 status 轮询在槽位释放后继续调度；重试时会隔离失效的旧报告，避免 schema 校验失败覆盖正在重跑的任务。
- **Tender stage live monitor avoids false timeouts** — The project Professional Process panel is now a live monitor with progress bars, elapsed timers, merge-safe refreshes, and session-event wakeups. Stage RPC client/handler timeouts are raised to 180s, and spawn idle activity timeout defaults to 60 minutes so long document-analysis children are not marked stale mid-run.
- **投标阶段实时监控避免误超时** — 项目页「流程监控」改为实时面板，含进度条、已运行时长、合并式刷新与会话事件唤醒；阶段 RPC 客户端/服务端超时提升至 180s，spawn 空闲超时默认 60 分钟，避免长文档分析中途被误判过期。
- **Monitor no longer auto-dispatches on open** — Opening a project only takes a status snapshot (reconcile board ↔ left-sidebar sessions). Idle ghost "running" slots are released to `pending` without spawning. Live **20s** polling and queue dispatch require an explicit **检查** then **恢复未完任务** (new `resume` action). Batch rows link to the matching left-tree child session.
- **流程监控不再打开即自动调度** — 打开项目只做 status 快照（任务板与左侧会话对齐）；空闲幽灵「运行中」槽位会释放为 `pending` 且不自动 spawn。开启监控后按 **20s** 轮询调度，需先点「检查」再点「恢复未完任务」（新增 `resume`）。批次行可跳转到左侧对应子会话。
- **Kimi K3 long-context + clearer compression/spawn UX** — Custom endpoints recognize `k3` / `kimi-k3` as 1M (and `k3-256k` as 256k) instead of the 128k default. Tool-result summarization hard-cap rises to 48k on ≥256k windows. Compaction banners and context-badge tooltips explain the ~16k reserve / ~20k keep-recent behavior, and spawn handoff-limit errors are rewritten to “max 4 active sub-agents”.
- **Kimi K3 长上下文与压缩/派发提示** — 自定义端识别 `k3` / `kimi-k3` 为 1M（`k3-256k` 为 256k），不再落到默认 128k；≥256k 窗口下工具结果摘要硬顶升至 48k。压缩横幅与上下文徽章说明约 16k 预留 / 近 20k 保留策略，并将 spawn 上限错误改写为「最多 4 个活跃子智能体」。
- **Restored/spawned sessions rebind business working directories** — Session tool context now lazily resolves `workingDirectory` from live session metadata / `session.jsonl`, and tender/delivery/investment handlers use that resolver. Restored parents and spawned children no longer fail business tools with a missing working directory when metadata already has the path.
- **恢复/派生会话重新绑定业务工作目录** — 会话工具上下文每次从实时会话元数据 / `session.jsonl` 懒解析 `workingDirectory`，投标/交付/投资 handlers 统一走该解析器。父会话恢复与子会话派生后，只要元数据已有路径，业务工具不再因工具上下文未绑定工作目录而失败。

- **Claude Agent SDK 升级到 0.3.226** — 从 0.3.222 升到 0.3.226（跨会话入站与 dialog expiry、resume 改进及相关硬化）。
