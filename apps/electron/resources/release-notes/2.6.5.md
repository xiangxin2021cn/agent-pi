# Agent Pi 2.6.5 / Agent 派 2.6.5

Agent Pi 2.6.5 keeps in-app Markdown file preview on a loading state until the file is actually read, compiles bid-binding **project characteristics** after document analysis (no separate boundary desk), blocks later pricing/planning from filling missing specs or site facts from model memory unless the user uploads sources or authorizes web diligence, and switches the tender/delivery/investment workbench UI with the app language instead of leaving Chinese hardcoded in English (and other) locales.

Agent 派 2.6.5 修正应用内 Markdown 文件预览：点击后保持加载态直到读完。招标文件解析合并后汇总「项目特征」，工作台不再单独设边界条件栏。组价/策划缺规范、合同或地质等原文时须补传或强制放行尽调，禁止用模型记忆填空。投标/实施/投资工作台界面随应用语言切换，不再在英文等界面里硬编码中文。

## Features

- **Project characteristics after document analysis, no boundary desk** — Tender workbench drops the「项目边界条件」column. After parse batches merge, Official Outputs writes `项目特征.md` (and a matching chapter in the parse synopsis) covering contract form/particular conditions, spec amendments, duration/site/geology/climate, working hours/holidays, subcontracting/localisation, and employer-imposed sequence. BOQ pricing uses that file as the brief instead of a confirmed `project_boundary` pack.
- **招标文件解析后汇总项目特征，去掉边界条件栏** — 投标工作台不再单独设「项目边界条件」阶段。解析批次合并后在正式输出写入 `项目特征.md`（解析纪要中同步专章），归纳合同制式与专用条款、规范及条文修订、工期地点地质气候、工时节假日、分包属地化、施工顺序等招标限定；BOQ 组价以此为依据，不再要求人工确认 `project_boundary` 围栏包。
- **Project characteristics evidence gate** — BOQ pricing and planning block when registered inputs are only a BOQ/drawing (no tender/spec/contract/geology source). The parent session is told to upload evidence and re-parse, or force-pass to authorize web diligence (`url` + `accessedAt`). Empty characteristic chapters stay non-blocking but must not be filled from model memory. Market-rate `webEvidence` stays a separate rule.
- **项目特征缺证据则禁止臆造** — 组价/策划阶段若已登记资料只有清单/图纸、没有招标文件或规范/合同/地质原文，工作台阻断并请主会话提示用户：补传后重新解析，或「强制放行」授权网络尽调（须留网址）。空章节不阻断，但不得用模型记忆填空。市场费率联网核证与此授权分开。

## Improvements

- **Workbench UI follows the app language** — Tender, delivery, and investment workbench chrome (stage names, overview cards, dialogs, toasts, live-monitor copy) uses `businessProjects.*` i18n keys in all seven bundled locales. Agent draft prompts and Official Output filenames stay in the original language so generated artifacts do not silently rename.
- **工作台界面随语言切换** — 投标、实施、投资工作台的阶段名、总览卡片、对话框、提示与实时监控文案走七种语言的 `businessProjects.*` 键。派发给 Agent 的草稿 prompt 与正式产物文件名保持原文，避免生成文件被悄悄改名。

## Bug Fixes

- **Large Markdown preview no longer flashes “no content”** — Opening a file overlay used an empty-string placeholder, which the markdown viewer treated as a finished empty file. Pending reads now stay on a loading state until `file:readPreview` returns (no client/handler timeout). Formatted Markdown rendering is unchanged; only the existing 1 MB preview-read cap still truncates.
- **大 Markdown 预览不再立刻显示无内容** — 点击后保持加载态直到读完；不再把空字符串当成读完。仍走原来的 Markdown 渲染；只有原有的 1 MB 预览读取上限会截断并提示用外部程序打开全文。
- **Session work products go to Official Outputs** — Tender stage files write to `Agent Pi Outputs/<sessionId>/`, the same Official Outputs folder each session already uses. Working Folder no longer lists that folder as a duplicate.
- **会话工作产物写入正式输出** — 投标阶段文件写入 `Agent Pi Outputs/<会话ID>/`，与会话正式输出同一目录；工作文件夹不再把该目录列为重复项。
