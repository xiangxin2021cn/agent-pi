# Agent Pi 2.0.0 / Agent π 2.0.0

Agent Pi 2.0.0 upgrades long-task execution from a prompt-only loop into a structured orchestration architecture.

Agent π 2.0.0 将长任务执行从单纯依赖提示词的循环，升级为可审查、可约束、可恢复的结构化编排架构。

## Highlights / 亮点

- **Structured task board** - Professional, Strict Delivery, and Multi-Agent Deep work now carries an explicit task board with scope, role, dependencies, allowed sources, forbidden actions, and expected handoff fields.
- **结构化任务板** - 专业文档、严格交付、多智能体深度模式会携带明确的任务范围、角色、依赖、允许来源、禁止动作和交接字段。
- **Plan / Audit / Merge separation** - Planning, verification, and final synthesis are separated so sub-agents provide evidence handoffs while the main session owns audited final merging.
- **Plan / Audit / Merge 分离** - 规划、审查和最终合成分离，子智能体负责证据交接，主会话负责审查后的最终合并。
- **Selected knowledge-base hard boundary** - When users load specific knowledge-base entries, source tools outside that selection are blocked and working-directory corpus discovery is intercepted unless the user expands scope.
- **选中知识库硬边界** - 用户加载特定知识库条目后，未选来源工具会被阻断，工作目录语料扫描会被拦截，除非用户明确扩大范围。
- **Structured human confirmation pause** - `<requires_user_decision>` blocks now pause Goal Loop for manual review instead of being hidden by automatic continuation.
- **结构化人工确认暂停** - `<requires_user_decision>` 会让 Goal Loop 进入人工审查暂停，不再被自动续跑掩盖。
- **Sub-agent lifecycle tracking** - Spawned sessions are recorded in parent goal state with working directory, selected source slugs, status, and expected handoff schema.
- **子智能体生命周期跟踪** - 派生会话会记录到主会话目标状态中，包括工作目录、选中来源、状态和预期交接格式。
- **Orchestration entropy monitoring** - The audit layer records warning/high entropy when many sources, sub-agents, tool failures, write failures, or workspace scans accumulate.
- **编排熵监控** - 审查层会记录多来源、多子智能体、工具失败、写入失败、工作目录扫描等造成的 warning/high 风险信号。
- **IWG-style regression tests** - New regression coverage protects selected-source boundaries, structured pauses, task-board prompts, pre-tool-use interception, and entropy signals.
- **IWG 风格回归测试集** - 新增回归覆盖选中来源边界、结构化暂停、任务板提示、工具前置拦截和编排熵信号。

## Safety Notes / 安全说明

This release intentionally tightens scoped-source execution. If a task should analyze the full working folder or additional knowledge bases, explicitly load or name those sources in the user request.

本版本会更严格约束“选中来源”任务。如果任务确实需要分析完整工作目录或额外知识库，请在用户指令中明确加载或点名这些来源。
