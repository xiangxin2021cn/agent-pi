# Agent Pi 2.1.0 / Agent π 2.1.0

Agent Pi 2.1 turns long-document work from a prompt-led process into a verifiable delivery protocol. Requirements, evidence, document sections, orchestration transitions, and completion gates now have application-owned state.

Agent π 2.1 将长文档工作从提示词驱动流程升级为可验证的交付协议。需求、证据、文档章节、编排阶段和完成门槛均由应用持久化管理。

## Highlights / 亮点

- **Stable requirement ledger** - Material deliverables, constraints, evidence, formats, and acceptance checks receive stable IDs. Follow-up requests extend the ledger without renumbering prior requirements.
- **稳定需求账本** - 关键交付物、约束、证据、格式和验收项获得稳定 ID；后续补充要求会扩展账本，不会重排既有要求。
- **Requirement provenance** - Final audits record requirement status, verification method, selected evidence references, verification time, and explicit failure reasons. The session Info popover exposes a bounded summary.
- **需求级证据追踪** - 最终审查记录每项需求的状态、验证方式、选中证据、验证时间和失败原因；会话“信息”弹窗展示受控摘要。
- **Transactional long Markdown** - Professional Markdown uses `document_artifact` section chunks, frozen hashes, atomic assembly, and post-assembly validation. Failed sections can resume without rewriting completed work.
- **事务型长 Markdown** - 专业 Markdown 通过 `document_artifact` 分章节写入、冻结哈希、原子组装并在组装后校验；章节失败后可续写，无需推倒已完成内容。
- **Executable Plan / Audit / Merge** - Dependency-aware transitions block audit, merge, or completion when scoped tasks, handoffs, required sections, or the final artifact are not ready.
- **可执行 Plan / Audit / Merge** - 当范围任务、交接报告、必需章节或最终产物未就绪时，依赖感知的状态机会阻止审查、合并或完成。
- **Complete-text audit** - Markdown, text, and JSON artifacts up to 5 MiB are audited in full while UI/model previews remain bounded. Oversized required audits fail closed to manual review.
- **完整文本审查** - 5 MiB 以内的 Markdown、文本和 JSON 产物会进行全文审查，同时保持 UI/模型预览受控；超限的强制全文审查会转入人工复核。
- **Current-turn completion proof** - Professional document completion accepts only a transactionally validated artifact that was deterministically verified as an output of the current turn. Historical files, read-only file access, and reviewer self-report cannot satisfy the delivery gate.
- **本轮交付证明** - 专业文档只有在事务校验产物同时被确定性确认属于本轮输出时才能完成；历史文件、只读访问和审查模型自述均不能通过交付门槛。
- **Final evidence package** - Goal Audit prefers a compact evidence package and rewrites it after reviewer and completion gates resolve, preserving the final requirement and artifact state.
- **最终证据包** - Goal Audit 优先使用紧凑证据包，并在审查与完成门槛结束后写回最终需求和产物状态。
- **Follow-up-safe recovery** - Follow-up instructions preserve reusable tasks, sub-agent lifecycle, reports, evidence, entropy signals, and progress state before explicitly resuming at Plan.
- **后续指令安全续跑** - 追加指令会保留可复用任务、子智能体生命周期、报告、证据、熵信号和进度，再从 Plan 阶段明确恢复。
- **Core runtime refresh** - Claude Agent SDK 0.3.206 adds command/background-task lifecycle signals and more accurate terminal states. Pi 0.80.6 improves Windows context discovery, long-run retry behavior, compaction accounting, truncated tool-call handling, and DeepSeek DS4 overflow detection.
- **核心运行时升级** - Claude Agent SDK 0.3.206 增加命令与后台任务生命周期及更准确终态；Pi 0.80.6 改进 Windows 上下文发现、长任务断流重试、压缩预算、截断工具调用处理和 DeepSeek DS4 溢出识别。

## Safety Notes / 安全说明

V2.1 does not enable recursive sub-agent spawning, broad working-directory scans as a default source, or silent bypass of required user confirmation. Pixel-perfect Word/PDF template cloning and exact claim-to-page/cell provenance remain future format-specific work.

V2.1 不启用递归子智能体派生，不把工作目录全量扫描作为默认来源，也不允许静默绕过人工确认。像素级 Word/PDF 模板复刻及精确到页码/单元格的声明溯源仍属于后续格式专项能力。
