# Agent Pi 2.6.2 / Agent 派 2.6.2

Agent Pi 2.6.2 hotfixes Session Files after the 2.6.0 on-demand tree: Official Outputs folders no longer stick on **Loading…**, and expanding `orchestration/briefs` (or `reports`) is not blocked behind a full working-folder walk.

Agent 派 2.6.2 热修 2.6.0 起按需加载的会话文件树：正式输出目录不再停在「加载中…」；展开 `orchestration/briefs` / `reports` 时不会被整个工作目录扫描堵住。

## Bug Fixes

- **Session Files stuck on Loading…** — Expanding a nested Official Outputs folder (e.g. `Agent Pi Outputs/<session>/orchestration/briefs`) could leave the row on **加载中…** forever. The tree treated effect cleanup as unmount, skipped clearing the loading pill, and refused a second fetch for the same path. Child loads now always clear, time out after 20s, retry on collapse/expand, and hydrate already-expanded placeholders after the first paint.
- **会话文件停在「加载中…」** — 展开正式输出下的子目录后，加载标记可能永远不掉，再次点击也不会重试。现已在成功/失败/超时后清掉加载态，并补上已展开占位目录的回填。
- **Working folder scan blocked Official Outputs** — Root `GET_FILES` listed the bound project at depth 1, so `node_modules` / CAD dumps occupied the main-process RPC thread and nested Official Outputs fetches never returned. Working folder and tender workspace roots now paint at depth 0; children load only when that folder is expanded. Official Outputs still lists one extra level so `orchestration/briefs` is visible immediately.
- **工作目录扫描堵住正式输出** — 根列表不再预扫工作目录的第二层；展开工作目录或投标工作区时再按需加载。正式输出仍先列出一层子目录。
