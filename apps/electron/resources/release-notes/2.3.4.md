# Agent Pi 2.3.4 / Agent π 2.3.4

Agent Pi 2.3.4 fixes a tender document-analysis retry loop caused by duplicate child section ids colliding with deep-equal merge gates and oversized inline tool payloads.

Agent π 2.3.4 修复招标文件分析重试死循环：子报告模板 section id 冲突导致确定性合并失败，主会话又为挤进工具入参反复压缩摘要，与深相等门禁互相打架。

## Bug Fixes / 修复

- **Document-analysis merge no longer fails on template section ids** — Final pack section ids are namespaced as `<documentId>--<sectionId>`, so 21 documents reusing `sec-01-...` / `sec-02-...` merge cleanly instead of aborting with dozens of duplicate-id errors.
- **document_analysis 合并不再被模板 section id 卡住** — 终包 section id 命名为 `<documentId>--<sectionId>`，即使各子报告复用 `sec-01-...` / `sec-02-...` 也能确定性合并，不再因重复 id 中止。
- **Parent agents cannot overwrite merges with compressed inline JSON** — When every batch report is complete, `tender_capability` init/replace for `document_analysis` always writes the deterministic batch merge and ignores truncated inline payloads. Prefer omitting `data` or using `dataPath` for other large packs.
- **主会话无法再用压缩内联 JSON 覆盖合并结果** — 全部批次完成后，`document_analysis` 的 init/replace 一律写入批次确定性合并结果，忽略被截断的内联载荷；其他大包优先用 `dataPath`。
- **Retry-loop guidance** — Tool descriptions and stage prompts explicitly forbid compressing summaries to fit tool-call size limits; stage status/resume remains the supported closeout path.
- **重试循环指引** — 工具说明与阶段提示明确禁止为迁就工具入参大小而压缩摘要；关闭阶段应走 status/resume。
