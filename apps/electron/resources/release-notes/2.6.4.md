# Agent Pi 2.6.4 / Agent 派 2.6.4

Agent Pi 2.6.4 raises the Windows spawn memory gate so chapter agents are not blocked by inflated working-set totals, keeps overflowed tender batches queued instead of failed, and stops GET_MESSAGES from truncating assistant markdown that in-chat table/preview blocks need.

Agent 派 2.6.4 放宽 Windows 上 spawn 内存门（不再把共享 DLL 的 working set 加总误判为超限），投标超限批次保持排队而不是失败，并停止截断助手正文，避免对话里的表格/Markdown 预览块解析失败。

## Improvements

- **Windows spawn cap uses private bytes and scales with RAM** — The Electron-family spawn gate no longer sums working set (which double-counts shared DLLs). On Windows it compares `privateBytes`; the default cap is 35% of physical RAM (floor 1.5 GiB), overridable with `CRAFT_SPAWN_TOTAL_WORKING_SET_LIMIT_KB` / `CRAFT_SPAWN_MEMORY_FRACTION`.
- **Windows spawn 上限改用 privateBytes 并按物理内存比例设顶** — 不再把各进程 working set 加总（共享 DLL 会重复计算）。Windows 比较独占 `privateBytes`；默认顶为物理内存的 35%（不低于 1.5 GiB），可用环境变量覆盖。
- **Idle agent dispose can drop unused transcripts** — After a child runtime is disposed and nothing is pending to disk, the main process may drop that session's in-memory messages. Switching the visible chat does **not** rewrite or unload other transcripts (that starved in-chat `file:read` previews).
- **空闲 runtime dispose 后可释放无用 transcript** — 子会话 runtime 已释放且没有待写入磁盘时，主进程可丢掉其内存消息。切换当前聊天**不会**重写/卸载其它会话（避免卡住对话里的 `file:read` 预览块）。

## Bug Fixes

- **Tender spawn memory pressure no longer marks queued batches failed** — Capacity errors from the live memory guard (`spawn_session blocked: total working set/private memory/main process memory`) now match the task-board pending path, so overflowed chapter agents stay queued instead of `failed`.
- **投标 spawn 内存超限不再把排队批次标成失败** — 现行内存门文案（working set / private memory / 主进程 RSS）纳入容量错误匹配，超限章节任务保持 `pending`，槽位空了再调度。
- **In-chat datatable / markdown-preview blocks keep full assistant markdown** — GET_MESSAGES no longer truncates `message.content` (only tool payloads). Preview fences stay parseable so `file:read` can load the referenced file.
- **对话内表格/Markdown 预览不再被截断** — GET_MESSAGES 不再截断助手正文（只截断工具结果），预览代码块保持完整，以便 `file:read` 加载引用文件。
