# Agent Pi 2.6.3 / Agent 派 2.6.3

Agent Pi 2.6.3 hotfixes stray `nul` files in the project working folder. Git Bash does not treat cmd.exe `2>nul` as the NUL device, so agent shell commands were creating a real file named `nul`. Those redirects are rewritten to `/dev/null` before execution.

Agent 派 2.6.3 热修工作目录里莫名出现的 `nul` 文件。Git Bash 不会把 cmd 的 `2>nul` 当成空设备，智能体一跑就会在项目目录写出名为 `nul` 的普通文件。现已在执行前把这类重定向改成 `/dev/null`。

## Bug Fixes

- **Stray `nul` files from Git Bash** — Agent Bash on Windows runs under Git Bash. Models often emit cmd.exe idioms such as `del foo 2>nul`. Git Bash has no `del` and treats `nul` as a filename, so stderr (`/usr/bin/bash: line 1: del: command not found`) is written into a 1 KB `nul` file in the working directory. Pre-tool-use now rewrites `>nul` / `2>nul` / `&>nul` (and quoted / `./nul` / `nul:` variants) to `/dev/null`. Permission checks treat `nul` as a discard target, not a write. Write/Edit to reserved device names (`nul`, `con`, `prn`, …) is blocked.
- **工作目录出现 `nul` 文件** — Windows 上 Bash 走 Git Bash；模型常写 `2>nul`。Git Bash 会把 `nul` 当成文件名写进工作目录。现已在执行前改写为 `/dev/null`，并禁止向 Windows 保留设备名写入。
