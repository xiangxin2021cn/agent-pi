# Agent Pi V2.2 Enterprise Tender Workbench Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use task checkboxes for tracking.

**Goal:** Deliver the first V2.2 Tender Intelligence Core vertical slice with a versioned project-local business model, deterministic readiness audit, application-owned persistence tool, and bounded professional skill.

**Architecture:** Add a small dependency-neutral `@agent-pi/business-core` package for pure tender schemas and audits. Adapt it into the existing session-tool registry through one project-local `tender_workspace` tool. Keep model state in inspectable JSON under the selected working directory and leave Goal Loop, document delivery, knowledge sources, and provider backends unchanged.

**Tech Stack:** TypeScript, Zod 4, Bun test, existing session-tools registry, project-local JSON artifacts, existing Skill format.

**Implementation Status:** MVP vertical slice implemented and verified on `codex/v2.2-enterprise-tender-workbench` on 2026-07-12. Dedicated register UI and downstream calculation packs remain post-MVP work.

## Global Constraints

- Working directories are output/project boundaries, not implicit source corpora.
- Only selected sources, attached files, and explicitly registered files may enter the Tender Workspace.
- No nested sub-agent spawning.
- No hard-coded rates or productivity benchmarks in Skill instructions.
- No licensed standard text bundled into the repository.
- Every requirement and evaluation criterion must preserve an exact source locator.
- Invalid cross-entity references must be rejected before persistence.
- Writes must be atomic and contained under `<working-directory>/.agent-pi/business/tender/`.
- The first slice must remain useful with both Claude and Pi/Claude-compatible models.
