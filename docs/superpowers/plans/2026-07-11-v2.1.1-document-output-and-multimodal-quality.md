# Agent Pi V2.1.1 Document Output and Multimodal Quality Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Correct output-format intent, separate internal review artifacts from final prose, add structured artifact capabilities, strengthen source-backed multimodal composition, and enforce reader-facing/export quality in V2.1.1.

**Architecture:** Extend the existing task contract, V2.1 `document_artifact`, visual registry, Markdown export, and deterministic Goal Audit. Add shared artifact and visual specifications, preserve `outputFormats` as a compatibility projection, and keep internal review data in contract/manifests rather than reader-facing Markdown.

**Tech Stack:** TypeScript, Bun test, existing shared/server-core/session-tools packages, Node.js filesystem and ZIP inspection utilities, existing Markdown/DOCX/PDF/HTML export pipeline.

## Global Constraints

- PDF must never be inferred from an input/source filename.
- No unrequested binary export may become a completion requirement.
- Existing V2.1 transactional Markdown behavior and complete-text audit remain intact.
- Existing selected-source, working-directory, and two-pass Goal Loop boundaries remain intact.
- No new native dependency is introduced.
- Unknown proprietary formats are existence-only until a dedicated adapter and validator exist.
- Internal audit metadata must not appear in reader-facing output by default.
