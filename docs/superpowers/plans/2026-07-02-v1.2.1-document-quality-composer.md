# Agent Pi V1.2.1 Document Quality Composer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a V1.2.1 document-quality layer that automatically chooses professional visual blocks, generates construction-grade schedule visuals where appropriate, respects uploaded reference templates, and audits Markdown/PDF/DOCX outputs before completion.

**Architecture:** Add a lightweight document composer layer above the existing Document Plan, Markdown/Mermaid renderer, Goal Loop, MinerU extraction, and Project Memory Lite. The layer should emit editable Markdown-first visuals, source-backed manifests, optional rendered SVG/PNG assets for export, and deterministic audit evidence. It must be additive and feature-flagged so ordinary chat, file preview, and fast tasks keep current behavior.

**Tech Stack:** TypeScript, Bun tests, existing `beautiful-mermaid`, existing `sharp`, existing Markdown preview/export pipeline, existing Goal Loop document-quality audit, existing Project Memory Lite, existing MinerU/AnySearch optional integrations.

Key conclusion: professional reports should not pick charts by decoration. They should pick visuals from the underlying evidence relationship: schedule, sequence, hierarchy, comparison, trend, distribution, part-to-whole, risk, geospatial location, or architecture. Construction reports especially need WBS-aware Gantt, baseline/current comparison, progress date, critical path, milestones, resource/cost curves, and risk/progress tables. Mermaid Gantt is useful as editable Markdown, but it is not enough for construction-grade schedule reporting by itself.

## Scope

### In V1.2.1

- Detect document domain and visual opportunities during writing.
- Maintain an industry-aware visual registry.
- Generate Markdown-first visual blocks: Mermaid, tables, HTML/SVG, and local image references.
- Add a professional construction schedule renderer for report-ready Gantt/S-curve assets.
- Add A3 landscape export sizing for dense construction Gantt and map-heavy engineering appendices.
- Add vertical document profiles for investment analysis, geospatial reporting, and simulation/CAE result reporting.
- Extract a `TemplateProfile` from uploaded reference templates and audit new output against it.
- Extend Goal Loop with `VisualBlockAudit` and `TemplateFidelityAudit`.
- Add a local-global Enterprise Knowledge Base source category that reuses the existing Source/MCP/file-memory stack for company knowledge; team/network knowledge bases are future expansion.
- Make all visual features opt-in by task context or user mode, with conservative limits.

### Not In V1.2.1

- No full drag-and-drop design editor.
- No automatic use of unverified data to draw charts.
- No mandatory network search for every report.
- No hard dependency on external SaaS renderers.
- No complete P6/Project/Candy export engine in this slice; schedule data model should be compatible with that future work.

## Product Modes

| Mode | Trigger | Behavior |
|---|---|---|
| Fast | Default chat or small edit | No hidden visual generation. Existing behavior remains. |
| Standard Document | Report/proposal/plan/manual detected | Adds tables, Mermaid, simple charts when strongly justified. |
| Professional Document | User asks for high-quality report or export | Adds visual registry, evidence requirements, and audits. |
| Strict Template | User uploads a reference template or asks to match one | Enforces structure, headings, depth, figure/table conventions, and export checks. |
| Construction Schedule | Construction plan/schedule/progress/tender detected | Uses construction visual profile and professional Gantt/S-curve rules. |
| Investment Analysis | Investment, valuation, fund, feasibility, IRR/NPV, return/risk detected | Uses investment table, return, risk, cash-flow, sensitivity, and portfolio visual rules. |
| Geospatial Engineering | Coordinate, route, site, corridor, parcel, map, GIS, GeoJSON, KML, SHP detected | Uses map layout rules with legend, scale bar, north arrow, CRS, and source attribution. |
| Simulation / CAE | ANSYS, Fluent, FEA, CFD, stress, displacement, temperature, contour, mesh detected | Uses simulation result table, contour, convergence, load-response, and time-history rules. |
| Enterprise Knowledge Base | User right-clicks a Markdown/TXT/JSON artifact and chooses to create an enterprise knowledge memory MCP | Shows a first-class global company-knowledge category, lets the user choose or create a category, and only enables the KB after explicit user selection. |

## Existing Enterprise Knowledge Base Foundations

The codebase already has most of the plumbing needed for an enterprise knowledge base. V1.2.1 should layer product semantics on top of the current source system instead of building a second connector stack.

Current foundations:

- The left sidebar already groups data sources as API, MCP, and local folders in `AppShell.tsx`.
- The second sidebar list already filters sources in `SourcesListPanel.tsx` by `SourceFilter`.
- Source details already support viewing and editing `config.json`, `guide.md`, `permissions.json`, and MCP tool permissions in `SourceInfoPage.tsx`.
- The "one sentence install" path already exists through `EditPopover` contexts such as `add-source`, `add-source-api`, `add-source-mcp`, and `add-source-local`.
- AnySearch MCP is a concrete recommended-source template with disabled install plus credential dialog in `recommended-sources.ts` and `SourcesListPanel.tsx`.
- Right-clicking a session file can call `createFileMemorySource`, which reaches `CREATE_FILE_MEMORY_SOURCE` and `file_memory_source_create`, creates a workspace source, and exposes a read-only file-memory MCP server.
- `file-memory-mcp-server` exposes manifest, search, and read-chunk tools with citation-oriented output.
- Runtime source activation already restarts Claude SDK and Pi turns after `source_test` so newly enabled MCP/API tools become callable on the next turn.

Main gap:

The current system treats mounted Markdown as a generic file-memory MCP source. It does not yet have a global enterprise knowledge registry, category selection, explicit per-workspace enablement, or a dedicated UI entry under Data Sources. Review status, team/shared network knowledge bases, and non-text formats should stay out of the MVP and be handled as later extensions.

MVP decisions:

- Scope: local-global enterprise KB for the current user. Team/network KB is a future联网型 expansion.
- Activation: enterprise KB sources are visible globally, but are not enabled in a workspace/session until the user explicitly selects them.
- Formats: only `.md`, `.txt`, and `.json` are supported for MVP file-memory indexing. PDF, DOCX, XLSX, images, scans, and folders require future extract/index flows.
- Review state: audit/review/approval states are future enhancements, not required in MVP.
- Primary creation path: right-click a generated `.md`/`.txt`/`.json` artifact in the right-side file panel, choose "Create Enterprise Knowledge MCP", select an existing category or type a custom category, then the source appears under left sidebar Data Sources -> Enterprise Knowledge Base.

## Industry Visual Registry

### Construction / Tender / Engineering Delivery

Use these visuals when data supports them:

- WBS hierarchy tree for section/package structure.
- Professional Gantt for construction schedule, using WBS bands, baseline bars, current bars, progress date, milestones, dependencies, critical path, and legend.
- Mermaid Gantt as the editable Markdown source for smaller schedules.
- S-curve for planned value, earned value, actual cost, or quantity progress.
- Resource histogram for labor/equipment/material peaks.
- Procurement/submittal schedule for long-lead items.
- Method statement flowchart for construction sequence.
- Site responsibility org chart and RACI matrix.
- BOQ/cost breakdown table, stacked bar, or waterfall.
- Risk matrix for quality, safety, schedule, commercial, and interface risks.

### Business / Consulting / Market Reports

- KPI summary table, trend line, bar ranking, waterfall, segmentation matrix, quadrant matrix, funnel, roadmap, evidence card.

### Investment / Finance / Feasibility

- Professional data table with units, currency, decimal precision, subtotal/total rows, source notes, and scenario columns.
- Cash-flow table, NPV/IRR summary, payback period, DSCR/LLCR table, sensitivity matrix, scenario waterfall, tornado chart, cumulative cash-flow curve, return bridge, risk-return scatter, portfolio allocation, and Morningstar-style 3x3 style matrix when the required inputs exist.
- Investment performance display should preserve period, currency, gross/net distinction, fee assumption, benchmark, calculation basis, and disclosure notes.

### Geospatial / Route / Site / Corridor Reports

- Location map, route alignment map, site boundary map, parcel/land-use overlay, heat map, choropleth, buffer/intersection map, elevation profile, chainage strip map, and map evidence panel.
- Every generated map must include title, legend, north arrow when direction matters, scale bar, coordinate reference system, data source, retrieval/export date, and caveat if coordinates are approximate.
- Supported data inputs should include GeoJSON, KML/KMZ, CSV with latitude/longitude, route chainage tables, and later SHP/GeoPackage if a parser is added.

### Simulation / CAE / ANSYS / CFD / FEA Reports

- Result summary table, mesh quality table, boundary condition table, convergence plot, residual plot, load-displacement curve, stress/strain contour image, displacement contour image, temperature contour image, mode-shape table, time-history plot, section/path result plot, and design check utilization chart.
- If only tabular simulation exports are available, generate professional line/contour/heatmap-style Markdown assets from the data and preserve units, load case, result component, coordinate system, timestep/frequency, min/max, and node/element scope.
- If proprietary result files are provided without a local parser, the agent should request or use exported CSV/images instead of pretending to read solver-native data.

### Legal / Compliance / Contract Review

- Clause traceability matrix, obligation register, risk heatmap, timeline of notice events, responsibility matrix.

### Software / Product / System Architecture

- C4-style context/container/component diagrams, sequence diagrams, state diagrams, dependency graph, roadmap, incident timeline.

### Research / Academic / Due Diligence

- Evidence map, methodology flow, source quality matrix, concept map, timeline, citation table, comparison table.

### Operations / Supply Chain / Logistics

- Swimlane process, handoff map, Sankey-style flow if supported data exists, inventory trend, bottleneck chart, route/location table.

## Visual Trigger Rules

The detector should score opportunities instead of forcing visuals.

| Text/Data Pattern | Preferred Visual | Minimum Evidence |
|---|---|---|
| tasks + dates + durations | Gantt or timeline | task names, start/finish or duration |
| tasks + dependencies + criticality | professional Gantt/network summary | predecessors or sequence logic |
| cost/quantity over time | S-curve or line chart | dated numeric series |
| investment cash flows by period | cash-flow table + NPV/IRR summary + cumulative curve | period, cash-flow amount, currency |
| investment drivers/scenarios | sensitivity matrix, tornado chart, scenario waterfall | base case and variable deltas |
| coordinates, routes, parcels, sites | map layout or route strip map | coordinates or geospatial file |
| mesh/result values by node/element/grid | contour/heatmap-ready asset + result summary | coordinates or mesh/result table |
| solver residuals/time steps/load cases | convergence or time-history chart | ordered numeric series |
| categories + numeric values | bar/table | category/value pairs |
| part-to-whole | stacked bar or pie | complete denominator |
| process steps/decisions | flowchart/BPMN-lite | ordered steps and decision points |
| roles/reporting | org chart | role hierarchy |
| roles vs responsibilities | RACI matrix | roles and activities |
| risks by probability/impact | risk heatmap/table | probability and impact labels |
| system components/interfaces | architecture diagram | components and relationships |

Do not generate a visual when source data is missing. Write an audit issue instead.

## Construction Gantt Requirements

The professional construction Gantt must support:

- WBS grouping with section/package headers.
- Summary bars and activity bars.
- Baseline start/finish and current start/finish.
- Actual start/finish and percent complete where available.
- Data date / progress line.
- Critical path highlighting.
- Milestones as diamonds.
- Dependency lines where density is manageable; otherwise show dependencies in a side table.
- Calendar scale by week/month, not just day.
- Legend and source note.
- Page-friendly layout for A4 landscape export.
- A3 landscape layout option for dense construction schedules, route maps, and appendix-grade diagrams.
- Stable SVG/PNG output for PDF/DOCX export.

Canonical schedule model:

```ts
export interface ScheduleTask {
  id: string
  wbs?: string
  parentId?: string
  name: string
  start?: string
  finish?: string
  durationDays?: number
  baselineStart?: string
  baselineFinish?: string
  actualStart?: string
  actualFinish?: string
  progressPercent?: number
  predecessors?: string[]
  critical?: boolean
  milestone?: boolean
  trade?: string
  responsibleParty?: string
  sourceRefs?: string[]
}
```

Outputs:

- `schedule-data.json` as source of truth.
- Mermaid Gantt block for editable Markdown when schedule size is small.
- `schedule-professional.svg` for report-ready rendering.
- `schedule-professional-a3-landscape.svg` when the task count, WBS depth, or date range needs larger layout.
- Optional `schedule-professional.png` for DOCX compatibility.
- Markdown figure block with caption, source, data date, and audit note.

## Professional Table Requirements

Any imported data table used in a professional document should be normalized before insertion:

- Preserve source file path, sheet/table name, extraction time, and unit assumptions.
- Detect and display units, currency, decimal precision, dates, totals, subtotals, and negative values consistently.
- Keep raw data in a sidecar file and write a report-ready table into Markdown.
- For investment tables, separate assumptions, calculation outputs, scenario results, and disclosures.
- For engineering/simulation tables, separate inputs, boundary conditions, results, checks, and warnings.
- Avoid over-wide tables in the main report; use a summary table in the body and a detailed appendix table or exported spreadsheet.

## Geospatial Output Requirements

Generated map visuals must be treated as professional figures, not decorative images:

- Store normalized spatial data as GeoJSON when possible.
- Store map style metadata separately so the map can be regenerated.
- Include legend, scale bar, CRS, source, date, and confidence notes.
- For route/corridor projects, support chainage labels and section bands.
- For site/parcel maps, support boundary, buffer, constraint, and overlay layers.
- If coordinates are incomplete or ambiguous, output a location evidence table instead of a misleading map.

## Simulation Output Requirements

Simulation visuals must preserve engineering context:

- Every plot must identify solver/source, load case, timestep/frequency, result component, units, coordinate system, and scope.
- Result contours must include min/max values, color scale, and whether values are averaged/unaveraged if known.
- Mesh and convergence plots should be included before final result claims when data exists.
- Imported ANSYS/CAE native files should be handled only through explicit supported parser/export paths. Otherwise the agent should ask for CSV/images or use user-provided screenshots with clear provenance.

## Release Acceptance Criteria

- Professional document tasks produce visibly richer Markdown when data supports it.
- Construction schedule outputs include WBS-aware Gantt with A4/A3 landscape options or a clear refusal/audit issue when schedule data is insufficient.
- Investment outputs use professional tables and analysis visuals with currency, period, benchmark/scenario, and disclosure context.
- GIS outputs include map metadata and do not invent coordinates or misleading map layers.
- Simulation/ANSYS outputs preserve units, load cases, result components, coordinate systems, and source provenance.
- Uploaded templates influence structure, headings, depth, table/figure captions, and audit results.
- All generated visuals are editable or source-traceable.
- PDF/DOCX exports do not lose charts.
- Enterprise KB sources are local-global for the current user, explicit, category-based, source-backed, permissioned, and available through the existing MCP/API/local source system after user selection.
- Feature is conservative by default and does not increase ordinary-task latency noticeably.

## Risk Controls

- **Performance:** cap visual count, render asynchronously, cache schedule SVGs by data hash, do not run on ordinary chat.
- **Hallucination:** visual renderer requires source data or explicit user input.
- **Professional misuse:** finance, GIS, and simulation visuals must preserve units, assumptions, source, and scope; otherwise emit a table or audit issue instead of a polished but unsupported figure.
- **Template overclaim:** mark unknown style fields as unknown; do not pretend exact DOCX typography was matched if not parsed.
- **Export fragility:** convert professional visuals to local SVG/PNG assets before export and preserve A3/A4 page intent in asset metadata.
- **User experience:** show status chips and audit reports; avoid frequent confirmation dialogs.
- **Long schedules:** summarize by WBS for main report, attach detailed CSV/JSON or separate appendix.
- **Large geospatial/simulation assets:** summarize in the report body and attach detailed data sidecars instead of embedding massive raw tables.
- **Knowledge leakage:** enterprise/company sources must be globally listed but explicitly enabled per user selection, and must not be silently merged into project-local memory or unrelated sessions.
- **Source type churn:** keep Enterprise KB as source metadata in the MVP so existing API/MCP/local routing, validation, and activation stay stable.
- **Stale indexes:** file-memory KB manifests need reindex or warning behavior when the underlying file changes.
- **Scope creep:** team/network KB, review status, folders, PDFs, Office files, scans, and images are future extensions; the MVP should only accept `.md`, `.txt`, and `.json`.
