# Agent Pi V2.3 Bounded Self-Harness Implementation Plan

> **For agentic workers:** implement each task with a failing test first. Do not add live code generation or let a model rewrite production code at runtime.

**Goal:** Reduce repeated tool-call failures and task drift, reuse proven recovery routes across similar tasks, convert explicit user quality corrections into regression cases, and make BOQ/template completion machine-verifiable.

**Architecture:** Extend the existing `SessionManager` + Goal Loop + file-backed orchestration architecture. A workspace-scoped Harness Store records sanitized execution experience, quality feedback, regression cases, and constrained policy assets. Current-turn recovery is immediate and bounded; cross-task changes are advisory or promoted only after deterministic evaluation.

**Tech Stack:** TypeScript, Bun test, existing session JSONL/orchestration artifacts, existing BOQ capability schemas, existing template profiles.

## Non-Negotiable Boundaries

- No runtime self-modifying code, generated shell commands, or executable policy payloads.
- The same identical tool call may be retried once; the second identical failure stops that route.
- Persist signatures, classifications, hashes, and trace references, not enterprise document contents, secrets, or literal file paths.
- A route recovered successfully in one task may be reused only as a compact advisory recipe.
- Global policy promotion requires target, held-out, and protected regression evidence and remains reversible.
- BOQ completion is based on exact item IDs, counts, schemas, child report equality, and contradiction checks, never on an LLM completion claim.
- Strict template completion is based on parsed template structure and exported artifact evidence, not a generic prompt saying “follow the template”.
