# V2.5 Tender Orchestration Rewrite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rewrite the tender workbench control plane so registration → document parsing (human-reviewed MD) → C5.1 BOQ pricing + resource schedule → planning/programme/cashflow/submission stays user-controllable, with bundled SANRAL knowledge templates and dual MSP+P6 XML gates.

**Architecture:** Keep `tender_workspace` / `tender_capability` as SoR. Replace auto-flood `start` dispatch with `start` (bind parent + init queue) + `advance` (fill up to stage `maxConcurrency`). Gate stage completion on human artifact review and probes, not on optional `evaluation_strategy`. Bundle C5.1/N2 templates under Electron resources with project `bindings.json` override. Collapse V2.4 `planning`+`submission` into `planning-and-submission` with three UI substeps.

**Tech Stack:** TypeScript, Bun test, Zod, existing Electron RPC (`runTenderStage`), React overview panel, file-backed task boards under `.agent-pi/business/tender/<projectId>/orchestration/`.

**Spec:** `docs/superpowers/specs/2026-08-10-v2.5-tender-orchestration-redesign.md` (Draft v0.2, decisions locked).

## Global Constraints

- Stage ids: `project-setup`, `tender-document-analysis`, `boq-five-step-pricing`, `planning-and-submission` (aliases: `planning`/`submission` → last).
- Default concurrency: document analysis `2`, BOQ pricing `1`, planning `1`; hard cap `3`.
- One parent session per stage; re-enter resumes, does not `openNewChat` by default.
- Child agents must not call `spawn_session`.
- `evaluation_strategy` must not block stage-2 completion.
- Progress exports must include both `tender-programme.msp.xml` and `tender-programme.p6.xml`.
- Knowledge templates ship in install bundle; project `bindings.json` may override paths.
- Human Artifact Gate: required MD/XML/DOCX missing or critical docs not human-accepted → stage/substep cannot complete.
- No full JSON schema rewrite; add normalize + gates only.
- Commits: only when the user asks, or at task end if the executing session was told to commit; otherwise leave dirty tree for review.
- Respond to the user in 中文 when summarizing progress.

```ts
export function normalizeSourceRef(value: unknown): { documentId: string; page?: number; sheet?: string; clause?: string; section?: string; cell?: string } | undefined {
  if (typeof value === 'string') {
    const documentId = value.trim().slice(0, 80);
    if (!documentId) return undefined;
    return { documentId };
  }
  if (!value || typeof value !== 'object') return undefined;
  const record = value as Record<string, unknown>;
  if (typeof record.documentId !== 'string' || !record.documentId.trim()) return undefined;
  // ... copy optional fields from boq-pricing normalizeSourceRef
  return { documentId: record.documentId.trim().slice(0, 80), /* optionals */ };
}

export function normalizeSourceRefs(value: unknown) {
  if (!Array.isArray(value)) return [];
  return value.flatMap((entry) => {
    const ref = normalizeSourceRef(entry);
    return ref ? [ref] : [];
  });
}
```
