# Agent Pi V2.2 Business Project Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep tender, delivery, and investment work inside independent professional project views while reusing the existing conversation runtime and adding the missing tender methodology and five-step pricing stages.

**Architecture:** Persist a workspace-level index of plugin project pointers and a project-local shell manifest. Persist explicit business context on sessions. Extend module routes to address either a project register or a project session, then render the existing ChatPage inside a compact module workflow shell.

**Tech Stack:** TypeScript, React, Jotai, Electron RPC, Bun tests, existing ChatPage and attachment/source components.

## Global Constraints

- The three plugins remain independent and may share only explicitly selected enterprise knowledge.
- Working directories are project/output boundaries, not implicit source corpora.
- Business sessions remain visible globally but module actions must not navigate to All Sessions.
- No second chat implementation, model picker, attachment pipeline, Goal Loop, or output sidebar.
- Tender includes WORK PLAN AND PROPOSED METHODOLOGY after project planning.
- Tender includes BOQ item-by-item five-step cost build-up with sourced or explicitly unverified inputs.
