# V2.6 项目边界条件 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task after product locks the design. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Insert a first-class `project-boundary-conditions` stage between document analysis and BOQ pricing; raise professional report quality by industry jargon; and hotfix runtime crashes from unbounded tool-output string accumulation.

**Architecture:** New capability `project_boundary` + stage in the existing tender orchestration control plane; SANRAL/C5.1 becomes profile `sa-sanral-highway`; BOQ briefs inject the boundary pack; pricing quality checks become strategy-keyed by `pricingStandard`. Report writing follows industry-role templates. Stability: cap `accumulateOutput` before V8 string limits.

**Tech Stack:** Existing Bun monorepo — `packages/business-core`, `packages/server-core`, `packages/session-tools-core`, `packages/shared`, Electron renderer Overview UI, bundled knowledge under `apps/electron/resources/knowledge/`.

**Spec:** `docs/superpowers/specs/2026-08-12-v2.6-project-boundary-conditions-design.md` (v0.2)

## Global Constraints

- Product locked D1–D9 (design §9 / §9A / §9B).
- **Ship P-1 stability hotfix before or as first commit of the 2.6 branch** — may release as 2.5.3.
- Preserve V2.5 soft-gate philosophy.
- Professional reports: industry jargon; minimal file/path meta (design §9A).
- i18n for new UI strings; version 2.6.0 at feature cut.
