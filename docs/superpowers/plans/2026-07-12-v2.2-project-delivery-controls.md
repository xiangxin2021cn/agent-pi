# V2.2 Project Delivery Controls Implementation Plan

## Product Boundary

Project Delivery Controls is an independent enterprise plugin. Its system of record is Delivery
Workspace under `<working-directory>/.agent-pi/business/delivery/<project-id>/`. It does not read or
write Tender Workspace or Investment Workspace private files.

The plugin must initialize from user-owned implementation inputs without tender data. A tender or
enterprise-knowledge import is an optional frozen evidence snapshot and cannot become an approved
delivery baseline without local mapping, deterministic validation, and user confirmation.

## Capability Packs

1. Contract and Scope Baseline: contract obligations, approved scope, BOQ, WBS, responsibility and
   acceptance baselines.
2. Programme and Progress Control: approved baseline programme, calendars, data date, actuals,
   remaining duration, forecast dates, critical path and recovery scenarios.
3. Resource and Procurement Control: labour, plant, material, subcontract, procurement packages,
   delivery dates, capacity and constraints.
4. Cost and Commercial Control: approved budget, commitments, actual cost, accruals, variations,
   forecast-to-complete and estimate-at-completion with exact decimal arithmetic.
5. Cash-Flow Control: planned, actual and forecast cash flow linked to programme and cost records.
6. Risk, Change and Decision Control: risks, issues, notices, changes, claims, decisions, owners,
   due dates and approval gates.
7. Reporting and Audit: period close, variance explanation, evidence completeness, management
   reports and immutable audit history.

## Ordered Delivery

1. Add the Delivery Workspace schema, deterministic readiness audit and direct-input regression
   fixtures.
2. Add a separate `delivery_workspace` tool and persistence root with optimistic revisions.
3. Add immutable tender/knowledge snapshot import and hash/staleness validation.
4. Implement capability packs in the order listed above, each with schema, audit, fixtures and Skill.
5. Add a dense Delivery Workspace UI with source, baseline, programme, resource, cost, cash-flow,
   change and reporting tabs.
6. Add Goal Controller gates for explicit approved-baseline, period-close and management-report
   completion claims.

## Acceptance Gates

- Delivery Workspace initializes and reaches core readiness with direct user input and no Tender
  Workspace present.
- A tender snapshot is copied and frozen; later tender changes do not mutate delivery records.
- A snapshot or knowledge item cannot satisfy an approved baseline gate by itself.
- All approved baselines cite active direct sources or locally verified snapshots.
- Delivery mutations cannot resolve outside `.agent-pi/business/delivery/<project-id>/`.
- Delivery tests assert that no tender or investment store is created.
- All financial reconciliation uses exact decimal arithmetic.
