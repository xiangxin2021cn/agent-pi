# Agent Pi V2.1.1 Document Output and Multimodal Quality Design

Status: approved for implementation on 2026-07-11.

## Objective

V2.1.1 corrects document-delivery semantics and separates reader-facing content from internal quality-control artifacts. It also introduces a truthful format-capability model and a source-backed multimodal specification layer without attempting to implement every proprietary engineering format.

V2.1.1 extends the V2.1 Requirement Ledger, `document_artifact` transaction, complete-text Goal Audit, visual registry, and Markdown export pipeline. It does not add a second document engine.

## Product Guarantees

1. Input/source formats never become output requirements merely because their names appear in the request.
2. PDF is generated only when the user explicitly requests PDF or confirms a high-confidence inferred deliverable.
3. Reader-facing output excludes evidence matrices, Goal Audit notes, task contracts, assumption registers, and visual audit manifests unless the user explicitly requests them in the final artifact.
4. Every requested output is represented as a structured artifact deliverable with origin and validation level.
5. The application distinguishes a file it can create from a professional format it can validate or round-trip.
6. Visuals are generated from explicit source data or clearly labelled explanatory input, carry usable captions and source provenance, and survive target-format export checks.

## 1. Structured Artifact Deliverables

`SessionTaskContract` gains `artifactDeliverables`. `outputFormats` remains as a compatibility projection during V2.1.1.

```ts
export type SessionArtifactKind =
  | 'document'
  | 'workbook'
  | 'presentation'
  | 'schedule'
  | 'model'
  | 'data'
  | 'other';

export type SessionArtifactOrigin = 'explicit' | 'template_inferred' | 'app_draft';
export type SessionArtifactValidationLevel = 'existence' | 'syntax' | 'schema' | 'round_trip';

export interface SessionArtifactDeliverable {
  id: string;
  kind: SessionArtifactKind;
  format: string;
  required: boolean;
  origin: SessionArtifactOrigin;
  validationLevel: SessionArtifactValidationLevel;
  templatePath?: string;
  capabilityId?: string;
}
```

Detection precedence is:

1. explicit UI format selection;
2. explicit output verb plus format or output filename;
3. strict template inference, such as a user asking to preserve an uploaded DOCX template;
4. app-native Markdown draft only when a professional document task requires an editable file but no formal format was requested.

An `app_draft` Markdown artifact may use the V2.1 transaction engine, but it must not imply PDF, DOCX, or another formal export. A source path such as `tender.pdf` or `template.docx` is never sufficient output intent.

## 2. Artifact Capability Registry

The shared registry describes what Agent Pi can truthfully do with each format.

```ts
export interface ArtifactFormatCapability {
  id: string;
  format: string;
  kinds: SessionArtifactKind[];
  generation: 'transactional' | 'native_export' | 'tool_backed' | 'unregistered';
  validationLevel: SessionArtifactValidationLevel;
  preview: 'native' | 'converted' | 'external' | 'none';
}
```

Initial registrations:

- MD: transactional, syntax validation, native preview;
- HTML: native export, syntax validation, native preview;
- DOCX: native export, schema-oriented package validation, converted/native preview;
- PDF: native export only when requested, structural/render validation, native preview;
- XLSX, CSV, JSON, TXT: tool-backed with format-specific validation;
- PPTX: tool-backed until slide rendering and overflow audit are available;
- unknown/proprietary extensions: unregistered, existence-only, never described as professionally validated.

Future P6 XML/XER, Microsoft Project XML, IFC, BCF, LandXML, GeoPackage, VTK, and solver formats plug into this registry through dedicated adapters and round-trip fixtures.

## 3. Reader-Facing and Internal Artifact Separation

`SessionDocumentPlan` gains an explicit visibility plan:

```ts
export interface SessionDocumentArtifactVisibilityPlan {
  readerFacing: string[];
  internal: Array<'evidence_matrix' | 'goal_audit' | 'assumption_register' | 'visual_manifest'>;
  appendices: string[];
}
```

Default professional-document behavior:

- final body: requested narrative, necessary tables/figures, concise source notes and references;
- internal: evidence matrix, audit rationale, unresolved assumption register, visual manifest;
- appendix: only items explicitly requested by the user or required by the supplied template.

Execution prompts state that internal artifacts are controls, not section requirements. Goal Audit fails reader-facing artifacts containing internal control headings or editorial phrases such as `Evidence Matrix`, `Goal Audit`, `Task Contract`, `Visual Manifest`, `模板推导`, or `本章扩展`, unless the task contract explicitly permits them.

The existing `_reviews` output remains the home for review evidence. Visual audit reasons remain in the visual manifest and are removed from visible Markdown; visible figures retain only reader-appropriate captions and source notes.

## 4. Multimodal VisualSpec

V2.1.1 adds a structured `VisualSpec` above Mermaid/SVG/table rendering:

```ts
export interface VisualSpec {
  id: string;
  kind: VisualKind;
  title: string;
  caption: string;
  altText: string;
  sourceRefs: string[];
  evidenceType: 'source_evidence' | 'data_derived' | 'explanatory' | 'generated_illustration';
  dataPath?: string;
  target: {
    formats: string[];
    pageSize?: 'A4' | 'A3' | 'letter' | 'slide' | 'auto';
    orientation?: 'portrait' | 'landscape';
  };
}
```

Validation rules:

- title, caption, alt text, evidence type, and at least one source reference are required;
- data-derived visuals require a data sidecar;
- generated illustrations are labelled as illustrations and cannot satisfy evidence requirements;
- technical visuals require units, coordinate system, load case, time basis, or other domain context when applicable;
- visual audit reasons are internal metadata, not visible prose;
- visual count is a genre-aware budget, not a universal target of twelve;
- export checks verify that referenced assets exist and that target page intent is preserved.

Vega-Lite-style declarative specifications may be added later for general data charts. Existing specialized Gantt, geospatial, simulation, professional-table, Mermaid, and SVG renderers remain valid adapters.

## 5. Quality and Export Audits

The deterministic document-quality audit adds:

- reader-facing cleanliness;
- table-line ratio and narrative balance;
- internal-artifact leakage detection;
- format-capability consistency;
- visual caption/source/alt-text completeness;
- target-format asset and page-intent checks.

Default table-density checks are warnings/score deductions rather than universal hard failures. Template-derived or data-document profiles may override the threshold. A professional narrative document with more than 45% table lines receives a readability issue unless the contract explicitly identifies it as a workbook, matrix, register, or table-led deliverable.

Export audit behavior:

- requested formats are mandatory; unrequested formats are not generated or audited;
- each produced file must match a structured deliverable;
- the capability registry determines whether the application may claim existence, syntax, schema, or round-trip validation;
- exported DOCX/PDF/HTML with visuals must retain referenced assets and page intent;
- unsupported proprietary formats remain `needs_review` unless an adapter provides stronger verification.

## Compatibility and Migration

- Existing persisted contracts without `artifactDeliverables` continue using `outputFormats`.
- New contracts derive `outputFormats` from required deliverables for existing Goal Controller checks.
- Existing Markdown-only transactions remain valid.
- Quick mode remains lightweight and does not create professional review artifacts.
- No new native dependency is required in V2.1.1.

## Verification

Completion requires regression tests proving:

1. `Read tender.pdf and write a report` does not require PDF.
2. `Export the report as PDF` requires PDF and only PDF.
3. strict DOCX template preservation creates a template-inferred DOCX deliverable.
4. unknown explicit extensions are recorded as existence-only and unregistered.
5. professional contracts mark evidence matrix, audit, assumptions, and visual manifest internal by default.
6. reader-facing audit rejects leaked internal headings and editorial process notes.
7. table-heavy narrative output receives a readability issue while an explicit matrix/register does not.
8. VisualSpec rejects missing provenance, alt text, and data sidecars.
9. visible visual Markdown omits audit rationale while the manifest retains it.
10. existing SVG/Mermaid A3/A4 DOCX/PDF/HTML export tests remain green.

## Out of Scope

- Universal generation of every proprietary engineering format.
- Pixel-perfect cloning of arbitrary PDF templates.
- Treating model-written XML or binary content as validated without a serializer and verifier.
- Automatic decorative image generation for technical reports.
- Replacing the V2.1 transactional Markdown core.
