# Agent Pi V2.2 Enterprise Tender Plugin Roadmap

Status: Tender Intelligence Core is the required foundation. Downstream packs must consume stable workspace IDs and must not independently rescan the project directory or reconstruct tender facts from chat.

## Shared Contract

Every pack consumes `project.id`, registered `document.id` values, `requirement.id`, `criterion.id`, `deliverable.id`, and `response.id`. New domain entities must preserve source locators and expose deterministic validation. Model judgment may propose mappings; only validated mappings enter the system of record.

## Delivery Order

| Order | Capability pack | Required inputs | Primary artifacts | Minimum acceptance gate |
| --- | --- | --- | --- | --- |
| 1 | Evaluation Strategy | Requirements, criteria, deliverables | Compliance register, score coverage, response priorities | All pass/fail, threshold, and weighted criteria have source locators and response ownership |
| 2 | BOQ-Specification-Drawing Reconciliation | Registered BOQ, specifications, drawings, requirements | BOQ hierarchy, item-source links, scope-gap register, quantity assumptions | Every analyzed item has BOQ location and supporting specification/drawing reference or an explicit unresolved gap |
| 3 | Construction Methodology and Execution Planning | Scope mappings, constraints, evaluation strategy | Method statements, work packages, temporary works and hold-point register | Methods trace to work packages, constraints, required evidence, and responsible deliverables |
| 4 | Integrated Schedule and Resource Planning | Work packages, quantities, calendars, constraints | WBS, activities, logic, milestones, baseline programme, resource demand | No open-ended activities, invalid predecessors, missing calendars, or unlinked contractual milestones |
| 5 | Cost and Cash-Flow Planning | BOQ items, quantities, resources, programme, price sources | Cost build-ups, rate provenance, cost-loaded schedule, monthly cash flow | No hard-coded rate without source; quantity, resource, rate, time, and cash-flow totals reconcile |
| 6 | Submission Assembly and Red-Team Audit | Deliverables, templates, response plans, verified evidence | Submission manifest, formatted deliverables, cross-reference audit, red-team findings | Tender Workspace is `ready`; required formats, templates, signatures, returnables, and evidence are verified |
| 7 | Post-award Project Controls | Awarded scope, baseline programme, budget, commitments, progress | Progress updates, forecast, earned value, change and risk registers | Baseline and current data remain versioned; forecast changes preserve reason, source, and approval state |

## Pack Boundaries

Each pack must provide:

1. a small versioned domain schema;
2. an application-owned persistence and validation tool;
3. a bounded Skill that uses selected sources only;
4. synthetic complete and incomplete regression fixtures;
5. a Goal Audit adapter only for explicit completion claims;
6. a dense operational UI only after model behavior is stable.

Packs may request human confirmation when source precedence, engineering interpretation, commercial assumptions, or approval authority is ambiguous. They must not turn unresolved assumptions into unconditional conclusions.

## Next Implementation Target

Implement Evaluation Strategy first because it uses the existing requirements and criteria without introducing quantity, scheduling, or pricing engines. Its first UI should be a compact register with source, criterion method, weight or threshold, response owner, evidence status, and coverage state. BOQ reconciliation follows only after this register is stable.
