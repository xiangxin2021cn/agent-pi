## P6 XML Findings

Source:

`E:\南非项目\投标项目\Namibia\纳米比亚硫酸厂项目\P6_Rev6_MasterRev1_Civil_ResourceSmoothed.xml`

Observed:

- Root `APIBusinessObjects`.
- Namespace `http://xmlns.oracle.com/Primavera/P6/V8/API/BusinessObjects`.
- 1 calendar, 1 project, 65 WBS records, 406 activities, 520 relationships.
- No resources, roles, activity code dictionaries, or activity code assignments.
- Normal activities use `Task Dependent`.
- Milestones use `Start Milestone` or `Finish Milestone`.
- Relationship logic is mostly `Finish to Start`; only 3 `Start to Start` links observed.
- Activity `Notebook` is useful for source provenance, for example predecessor basis from source PDFs.

Feasibility:

P6 XML generation is feasible for V1.2 if the agent first creates a neutral schedule model, then writes namespace-aware BusinessObjects XML with stable ObjectIds and references.

## Microsoft Project XML Findings

Source:

`E:\南非项目\投标项目\Namibia\温得和克医院\温得和克医院\投标过程资料\WHK_Hospital_Master_Programme_Contract_Calendar_Manual.xml`

Observed:

- Root `Project`.
- Namespace `http://schemas.microsoft.com/project`.
- 1 calendar, 99 tasks, 47 resources, 0 assignments, 102 predecessor links.
- Seven-day calendar with 08:00-12:00 and 13:00-17:00 working periods.
- Summary tasks represent WBS headings.
- Leaf tasks carry durations, start/finish dates, WBS values, predecessor links, and `Notes`.
- Resource dictionary exists but the schedule is not resource-loaded.

Feasibility:

Microsoft Project XML generation is feasible for V1.2 and is simpler than P6 XML. The first version should generate summary tasks, leaf activities, predecessor links, optional resource dictionaries, and a validation report.

## Candy Findings

Source:

`E:\南非项目\投标项目\South Africa\N2 high way\Submit documents\!47967_!12827_SANRAL_Route_N2_section_18_tender_V01~03_Planning_Program.CCS.ccs_tmp`

Observed local structure:

- The file is not text XML/CSV.
- A Microsoft Cabinet `MSCF` signature appears at byte offset 4096.
- The CAB stream lists `BACKUP.DAT`.
- Expanded body is about 4.48 MB and contains Candy/SitePlan style markers, including `Tender Programs`, `SITEPLAN\A-__05*.A40`, `[Contract Dates]`, activity IDs, and activity descriptions.
- The body remains proprietary binary data, not a stable public schema.

Official RIB references:

- P6 to Candy import: https://www.rib-software.com/pdf/en/data-exchange-candy-primavera.pdf
- Microsoft Project to Candy import: https://www.rib-software.com/pdf/en/data-exchange-candy-ms-project.pdf

Official path:

- Candy imports Primavera P6 XML through Program Manager > Tools > Import > General importer.
- Candy imports Microsoft Project XML through Program Manager > Tools > Import > General importer (XML).
- Candy shows an analysis report after import.
- Primavera P6 XML import covers WBS, activity IDs, descriptions, durations, dates, and logic, but not resources.
- Microsoft Project XML import covers dates, calendars, summary headers, activity IDs, descriptions, durations, start/end dates, and precedence logic, but not resources or resource calendars.

Feasibility:

Candy-compatible output is feasible in V1.2 by generating P6 XML or Microsoft Project XML for Candy General Importer. Native `.ccs` or `.ccs_tmp` generation should remain experimental until round-trip validation inside Candy is available.

## Recommended V1.2 Product Shape

Ship the skill as an agent capability, not as a silent auto-converter:

1. User asks for a construction programme.
2. Agent reads source documents and builds a neutral schedule model.
3. Agent exports one or more target formats.
4. Agent writes a validation report next to the output.
5. For Candy, agent labels the output as Candy General Importer XML unless actual native Candy import has been verified.

This keeps the app useful immediately while avoiding risky claims about proprietary Candy backup writing.
