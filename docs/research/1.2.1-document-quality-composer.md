# V1.2.1 Document Quality Composer

Date: 2026-07-03

## Purpose

V1.2.1 adds a conservative document-quality layer for professional project reports. The goal is to improve generated Markdown, PDF, and DOCX deliverables with source-backed visuals, professional tables, export-stable assets, template-fidelity audits, and reusable Knowledge Base sources.

This is not a decorative chart feature. A visual block is allowed only when the task, data, and evidence support it.

## Operating Principles

- Markdown remains the editable semantic draft.
- Exported PDF/DOCX must receive stable local assets rather than unresolved preview-only blocks.
- Mermaid is preferred for small editable diagrams and schedules.
- Professional SVG/PNG assets are preferred for dense construction schedules, maps, engineering figures, and appendix-grade visuals.
- Every figure or table must preserve caption, source note, data date or retrieval date when available, and audit reason.
- Missing data should produce an audit issue or evidence table, not a polished invented visual.
- Strict template fidelity is code-level work: prompt-only style instructions are not enough.

## Visual Registry

The visual registry maps evidence patterns to professional visual types.

| Domain | Trigger | Preferred visual | Required evidence |
| --- | --- | --- | --- |
| Construction/tender | tasks, dates, WBS, milestones | WBS-aware Gantt, S-curve, resource histogram, method flow, RACI | activities plus dates/durations or sequence data |
| Investment/finance | cash flows, return, risk, scenarios | professional table, NPV/IRR summary, sensitivity matrix, waterfall, cumulative curve | periods, currency, values, assumptions |
| GIS/route/site | coordinates, chainage, boundary, route | location map, route strip, chainage map, overlay map | coordinates, CRS or source caveat |
| Simulation/ANSYS/CAE | residuals, load cases, result values | convergence plot, time-history, result summary, contour-ready figure | solver/source, units, load case, component, scope |
| Contract/legal | clauses, obligations, dates, risks | traceability matrix, obligation register, risk heatmap, notice timeline | clause references or dated events |
| Software/product | components, flows, states | C4-style diagram, sequence, state diagram, dependency graph | named entities and relationships |

## Construction Gantt Behavior

Construction and tender reports require a stronger schedule visual than a plain Mermaid Gantt when the data is dense or professional delivery is requested.

The professional construction schedule renderer should support:

- WBS grouping and summary bands.
- Baseline bars and current-plan bars.
- Actual progress and percent complete where available.
- Data date / progress line.
- Critical path highlighting.
- Milestones as diamonds.
- Dependency display when legible, otherwise a dependency table.
- Legend, source note, and schedule data date.
- A4 landscape export for ordinary reports.
- A3 landscape export for dense schedules, route schedules, and appendix-grade diagrams.

Expected artifacts:

```text
schedule-data.json
schedule-professional.svg
schedule-professional-a3-landscape.svg
schedule-professional.png
```

Markdown should reference the rendered asset and preserve source metadata:

```markdown
![Professional construction schedule](./assets/schedule-professional-a3-landscape.svg)

**Figure 3. Construction schedule, WBS level 2.**  
Source: schedule-data.json extracted from project programme and BOQ package split.  
Data date: 2026-07-03. Page intent: A3 landscape.
```

## Investment Visual Constraints

Investment tables and charts must preserve:

- currency;
- period;
- gross/net basis;
- benchmark or scenario basis;
- discount rate or return calculation assumptions;
- fee and tax assumptions when used;
- source date and source file.

Recommended visuals include:

- assumptions table;
- cash-flow table;
- NPV/IRR summary;
- payback/DSCR table;
- sensitivity matrix;
- tornado chart;
- waterfall;
- cumulative cash-flow curve;
- risk-return scatter.

Do not calculate or chart investment metrics when the necessary assumptions are missing. Output a missing-input table instead.

## Geospatial Visual Constraints

Maps and route visuals must be treated as evidence figures.

Required metadata:

- title;
- legend;
- scale note or scale bar;
- CRS or explicit "CRS unknown" warning;
- source;
- retrieval/export date;
- coordinate confidence.

Supported MVP inputs:

- GeoJSON;
- CSV with latitude/longitude;
- route or chainage tables;
- user-provided map images with provenance.

If coordinates are incomplete or ambiguous, create a location evidence table instead of a map.

## Simulation And ANSYS/CAE Constraints

Simulation visuals must not become free-form illustrations. Every result figure needs:

- solver/source;
- solver version when known;
- load case;
- result component;
- units;
- coordinate system;
- timestep/frequency where applicable;
- mesh/result scope;
- min/max values or result range where available.

Supported MVP sources are exported CSV/tables/images with provenance. Native proprietary solver files should be processed only through an explicit parser or user-provided export path.

## Strict Template Mode

Strict template mode is triggered when the user uploads or references a template and asks the app to keep its format, page layout, heading structure, or writing depth.

Important boundary:

- Markdown is not a high-fidelity page layout format.
- Markdown can store semantic structure, headings, figures, tables, citations, and template profile IDs.
- Word-level fidelity requires DOCX/OOXML template parsing and DOCX rendering.
- PDF templates support visual approximation only unless a DOCX source template is also available.

Template profile extraction should record:

- page size and orientation;
- margins;
- header/footer references;
- styles.xml heading/body/table style IDs;
- numbering.xml outline rules;
- section order;
- average section depth;
- table and figure caption conventions;
- citation style and language tone.

Audit rules:

- Strict DOCX template claims require extracted OOXML evidence.
- Prompt-only claims must fail strict audit.
- Unknown style fields must remain unknown instead of guessed.
- PDF-only templates should be labeled "visual approximation".

## Knowledge Base Sources

V1.2.1 adds a first-class Knowledge Base category over the existing source system.

MVP behavior:

- A right-side generated `.md`, `.txt`, or `.json` artifact can be added to Knowledge Base.
- The app asks for a category/folder, using AI suggestion plus local deterministic fallback.
- The source remains an MCP file-memory source; no new `SourceType` is introduced.
- Source metadata includes `metadata.category: "knowledge_base"`, `collectionId`, `knowledgeCategory`, `knowledgeFolder`, `scope`, `sourceKind`, `fileExtension`, and `sourceFilePath`.
- The app-level registry records the current user's local-global KB catalog.
- The source appears under Data Sources -> Knowledge Base for the workspace where it was created.
- The source remains disabled unless the user explicitly enables/selects it.
- KB sources must not be silently merged into Project Memory Lite.

Future extensions:

- folder indexing;
- PDF/DOCX/XLSX/image extraction into KB entries;
- remote MCP/API enterprise KB connectors;
- team/network shared KB;
- review/approval status;
- sync and stale-index detection;
- permission governance by category, team, and source.

## Markdown Writing Template

Use this shape for source-backed professional figures:

```markdown
![Figure title](./assets/figure-id.svg)

**Figure N. Short caption.**  
Evidence: why this visual supports the surrounding claim.  
Source: title or file path, author/organization, publication date or extraction date, URL if applicable.  
Audit: generated from verified data; missing assumptions are listed below.
```

Use this shape for data tables:

```markdown
| Item | Unit | Base case | Downside | Upside | Source |
| --- | ---: | ---: | ---: | ---: | --- |
| Revenue | USD m | 10.0 | 8.5 | 12.0 | model-inputs.xlsx, Sheet Assumptions |

Table N. Scenario assumptions. Currency: USD. Values rounded for display only.
```

Use this shape when data is insufficient:

```markdown
### Visual Not Generated

The requested map was not generated because the input table did not include coordinates or CRS information.

| Missing input | Why it matters | Required action |
| --- | --- | --- |
| Latitude/longitude | Required to locate features | Provide coordinate columns or GeoJSON |
| CRS | Required for scale and distance | Confirm EPSG code or source CRS |
```

## Export Rules

- Resolve local Markdown image paths relative to the source Markdown file.
- Convert Mermaid blocks to stable SVG during PDF/DOCX export without changing the Markdown source.
- Preserve A3/A4 page intent from rendered professional assets.
- Fail loudly when a referenced local image is missing.
- Never export blank figures silently.

## No-Fabrication Checklist

Before accepting a professional document:

- Does every visual have source evidence?
- Does every chart preserve units and period?
- Does every investment visual preserve currency and assumptions?
- Does every map preserve CRS/source/date or warn when unknown?
- Does every simulation visual preserve solver/load case/component/units?
- Does every strict template claim have extracted template-profile evidence?
- Does every local image reference resolve during export?
- Are unsupported visuals converted into missing-input tables instead of invented figures?
